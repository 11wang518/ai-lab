# 专有名词解释

## 一、大模型部分

### 1. 模型规模

| 名词 | 大白话 | 在你项目里的对应 |
| --- | --- | --- |
| 大模型 / LLM | 用海量文字训练出来的"文字接龙机器"：给它前文，它猜下一个字 | 就是聊天面板里回答你的那个东西 |
| 参数 | 模型内部的"旋钮"数量，旋钮越多越聪明、也越占地方 | 训练就是调这些旋钮 |
| B | Billion，十亿。参数量的单位 | 7B = 70 亿个旋钮 |
| 2B 级 | 20 亿参数上下这一档的小模型 | 你选的 `qwen2.5:1.5b` 就在这一档 |
| 量化 / Q4 | 把每个旋钮从 16 位压成 4 位保存，体积缩到约四分之一，效果损失不大 | 显存小的时候全靠它 |
| GGUF | 一种专门为量化设计的模型文件格式 | 从魔搭、HuggingFace 下模型时常见后缀 |
| 权重 | 训练好的那堆参数，存成文件就是权重 | Ollama 拉下来的模型就是权重 |

### 2. 运行相关

| 名词 | 大白话 | 在你项目里的对应 |
| --- | --- | --- |
| 显存 / VRAM | 显卡自带的独立内存，和电脑的内存是两回事 | 你的 4060 是 8 GB |
| 推理 | 用训练好的模型算一次结果 | 你说一句话它回一句，就是一次推理 |
| Token | 模型眼里的"字"。中文大约 1 个字算 1~2 个 token | —— |
| token/s | 每秒能生成多少 token，用来衡量快慢 | 1.5B 在 4060 上大约 40~70 |
| 上下文 | 模型一次能"记住"的全部内容 | 上下文越长越吃显存 |
| 温度 / temperature | 随机程度。0 最死板，1 最发散 | 项目默认 0.7 |
| 首 token 延迟 | 从你发问到它吐出第一个字的等待时间 | 本机大概零点几秒 |

## 二、YOLO 与视觉部分

| 名词 | 大白话 | 在你项目里的对应 |
| --- | --- | --- |
| YOLO | 一种"看一眼就知道图里有什么、在哪儿"的检测算法，特点是快 | 检测面板背后的模型 |
| 目标检测 | 不只是说"图里有车"，还要框出车在哪 | 你要跑通的任务 |
| 检测框 / bbox | 框住目标的矩形，用左上角和右下角的坐标表示 | 前端画在图片上的框 |
| ultralytics | YOLO 官方维护的 Python 库，训练和推理都封装好了 | `pip install ultralytics` |
| 权重 / `.pt` | PyTorch 格式的模型文件 | `yolo11n.pt`、`best.pt` |
| 预训练权重 | 别人在大数据集上练好的模型，你拿来接着用 | 迁移学习的基础 |
| 迁移学习 / 微调 | 不从头练，站在别人的基础上再练 | 训练脚本默认这么干 |
| 标注 / label | 人工告诉模型"这张图里车在哪个位置" | 和图片一一对应的 txt 文件 |
| 类别 / class | 要检测的东西有哪几种 | 例如 car / person / bus |
| 数据集 / data.yaml | 图片 + 标注 + 一份说明文件 | `yolo/data.example.yaml` |
| epoch | 把所有训练数据完整看一遍，叫一轮 | 默认 50 轮 |
| batch | 一次同时喂几张图给模型 | 8G 显存建议 4~8 |
| imgsz | 训练和推理时把图片缩放到多大 | 默认 640 |
| conf / 置信度 | 模型有多确定这里是个目标 | 默认 0.25，低于它就不显示 |
| IoU | 两个框重叠了多少，用来判断是不是同一个目标 | —— |
| NMS / 非极大值抑制 | 同一个目标被框了好几次，只留最好的那个 | 前端降级方案也做了简易版 |
| mAP / mAP50 | 衡量检测好坏的分数，越高越好 | 训练脚本结束时会打印 |
| 实时推理 | 一边取画面一边检测，追求每秒多少帧 | `yolo/realtime.py` |
| FPS | 每秒处理多少帧 | 实时窗口左上角显示 |
| ONNX / TensorRT / OpenVINO | 把训练好的模型换成别的格式，跑得更快 | `yolo/export.py` |
| FP16 / INT8 | 半精度 / 8 位整数，牺牲一点精度换速度 | `--half` 参数 |
| AMP | 自动混合精度，训练时省显存 | 默认开启 |
| CUDA | 英伟达显卡的计算平台 | `torch.cuda.is_available()` 查它 |
| PyTorch / torch | 训练深度学习模型最常用的框架 | ultralytics 依赖它 |

## 四、这几组最容易混的概念

**参数 vs 显存**
参数是模型的"大脑大小"，显存是显卡的"桌面大小"。
模型越大，需要占的桌面越大；量化就是想办法把大脑压小一点塞进去。

**训练 vs 推理**
训练是"学习"，很慢、很吃资源，需要数据集和标注；
推理是"考试"，很快，用户平时用的都是推理。
你作业里"跑通一次训练"和"实时推理部署"就是这两个阶段。

**本机跑 vs 云端跑**
本机跑不花钱、数据不出门，但受显存限制；
云端跑不受硬件限制，但要联网、要花钱、数据要发出去。
本项目两种都支持，改一个环境变量就能切。

**准确率 vs 速度**
YOLO 的数字后缀就是这个权衡：`n` 最小最快，`s`、`m`、`l`、`x` 依次变大变准变慢。
8G 显存从 `n` 开始最稳妥。
