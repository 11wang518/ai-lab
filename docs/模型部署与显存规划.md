# 8G 显存（RTX 4060）本地大模型部署笔记

## 一、为什么选 2B 级千问

RTX 4060 是 8GB 显存。显存里要同时放三样东西：

1. 模型权重；
2. KV Cache（上下文越长占用越大）；
3. 推理时的中间激活。

按 4bit 量化的经验值粗算：

| 模型规模 | 权重占用 | 4K 上下文 KV Cache | 8G 显存结论 |
| --- | --- | --- | --- |
| 1.5B ~ 2B | 约 1.0 ~ 1.3 GB | 约 0.3 ~ 0.6 GB | 很宽裕，可以开长上下文 |
| 3B | 约 2.0 ~ 2.4 GB | 约 0.6 ~ 1.0 GB | 够用，推荐 4K 上下文 |
| 7B | 约 4.4 ~ 5.0 GB | 约 1.2 ~ 2.0 GB | 勉强能跑，要压上下文并关掉其他程序 |
| 14B | 约 9 GB+ | — | 8G 显存跑不动，需要更大显存或 CPU 混合 |

结论：**2B 级是本机的甜点区**，速度、显存、效果三者平衡最好。

## 二、模型选择

| 模型 | 下载体积(约) | 适合场景 |
| --- | --- | --- |
| `qwen2.5:1.5b` | 约 1 GB | 默认选择，中文流畅，响应快 |
| `qwen2.5:3b` | 约 2 GB | 需要一点推理能力时 |
| `qwen2.5-coder:1.5b` | 约 1 GB | 代码补全、脚本生成 |
| `qwen3:1.7b` | 约 1.4 GB | 带思考模式的新版本 |

Ollama 直接用标签拉取，例如 `ollama pull qwen2.5:1.5b`。
用 HuggingFace / 魔搭下载时，优先选带 `Q4_K_M` 或 `Q5_K_M` 的 GGUF 文件：
这两个量化档位在 8G 显存上基本无损可用。

## 三、三种部署方式对比

| 方式 | 安装成本 | 上手难度 | 适合谁 |
| --- | --- | --- | --- |
| Ollama | 装一个安装包 | 最低，两条命令 | 首选，本项目默认对接 |
| LM Studio | 装一个安装包 | 低，纯图形界面 | 不习惯命令行 |
| llama.cpp | 需要编译或下 release | 中，参数要自己调 | 想抠性能、想跑在无 Python 环境 |

三者在应用侧是同一件事：**都提供 HTTP 接口**，本项目用 `AILAB_LLM_PROVIDER`
和 `AILAB_OPENAI_BASE_URL` 两个变量就能切换，代码不用改。

## 四、实际操作步骤（以 Ollama + qwen2.5:1.5b 为例）

```powershell
# 1. 安装 Ollama
#    https://ollama.com/download  下载 Windows 安装包，一路下一步

# 2. 确认服务在跑
ollama --version
curl http://127.0.0.1:11434/api/tags

# 3. 拉模型
ollama pull qwen2.5:1.5b

# 4. 先单独试试模型本身
ollama run qwen2.5:1.5b "用一句话说明什么是目标检测"

# 5. 接进本项目的应用
cd D:\tools\codex\ai-lab
python run_server.py --provider ollama --model qwen2.5:1.5b
```

打开 <http://127.0.0.1:8000>，顶栏状态点变绿、显示 `Ollama 本地模型 · qwen2.5:1.5b`
就说明接通了。

## 五、性能调优

**关键参数**（Ollama 的 `Modelfile` 或启动环境变量）：

| 参数 | 含义 | 8G 显存建议 |
| --- | --- | --- |
| `num_gpu` | 放到显卡上的层数 | 默认自动，显存不够时手动调小 |
| `num_ctx` | 上下文长度 | 2048 ~ 8192，越大越吃显存 |
| `num_batch` | 批大小 | 512 左右 |
| `temperature` | 随机性 | 0.7 通用，写代码用 0.2 |

**实测参考**（RTX 4060 Laptop 级别，`qwen2.5:1.5b` Q4）：

- 短问题首 token 延迟约 0.1 ~ 0.3 秒；
- 生成速度约 40 ~ 70 token/s；
- 开 4K 上下文时显存占用约 2.5 GB，还有充足余量。

## 六、和 YOLO 抢显存怎么办

两个任务同时跑在同一块 8G 卡上时：

1. 把大模型的 `num_ctx` 压到 2048；
2. YOLO 训练时先停掉 Ollama（`ollama stop` 或直接退出托盘程序）；
3. 训练用 `yolo11n.pt` + `batch 8`，推理用 `realtime.py --half`；
4. 实在紧张，就把 YOLO 推理拆到 `yolo/serve.py` 独立进程，训练时单独跑。
